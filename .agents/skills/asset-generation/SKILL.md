# Asset Generation

## Purpose and use

Handle visual asset tasks while preserving approved art direction and existing assets. Do not use for unrelated feature work or assume that an asset pipeline already exists.

## Required context

Read `AGENTS.md`, `docs/AI_WORKFLOW.md`, relevant `docs/GAME_DESIGN.md` sections, and any approved visual standards in future `docs/ART_DIRECTION.md` if it exists. Inspect the requested asset, existing assets, intended project path, and available PixelLab MCP tools.

## Procedure

1. Determine the requested asset, its use, constraints, expected output path, and whether approved visual standards exist.
2. Prefer free, read-only inspection for planning. Discover the PixelLab tool for the specific operation and consult its targeted help before unfamiliar use; do not load unrelated capability descriptions. Verify each tool response.
3. Stop before production generation if required art direction is missing. Obtain explicit approval or confirm an authorized budget before any operation that consumes credits.
4. Produce only the approved asset scope, preserve existing approved assets, and inspect output before accepting it.
5. When supported, record relevant generation parameters, asset identifiers, costs, and intended paths in the delivery report or authorized project documentation. Coordinate import checks with `game-validation` when applicable.

## Approval and failure boundaries

No paid generation without approval or budget. Never expose credentials. Do not overwrite approved assets or use an unsupported tool operation silently. Report failed or uncertain tool results and stop dependent work.

## Expected output

Asset files or a production-ready plan, inspected results, known costs and identifiers where available, validation, and unresolved art-direction questions.
